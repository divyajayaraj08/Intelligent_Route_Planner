## Verification

- Backend: `npm --prefix D:\SmartRoute\smartroute\server test` — 41 pass, 0 fail, 1 skipped. The skipped test is the real Atlas persistence/restart test because SRV DNS lookup is refused.
- Frontend: `npm --prefix D:\SmartRoute\smartroute\client run build` — passed; Vite reports the main chunk is slightly above 500 kB.
- Nominatim/OSRM live arbitrary-coordinate tests: Chennai Central Railway Station → Marina Beach, Chennai: HTTP 200, 4.2 km, 5.2 min, 108 geometry points; Tirunelveli Railway Station → Government College of Engineering, Tirunelveli: HTTP 200, 7.0 km, 6.9 min, 176 points; Chennai Central → Bengaluru City Railway Station: HTTP 200, 332 km, 252.6 min, 4,939 points.
- A later direct Nominatim recheck returned HTTP 503 for both a real query and a no-match query, indicating current provider unavailability. The UI/API now report this as an error rather than a fabricated result. Previously successful live route tests remain evidence that arbitrary coordinates routed correctly when the provider was available.
- Browser: searched and selected Marina Beach Chennai and Chennai Central Railway Station through suggestion lists; selecting the second result triggered OSRM and displayed the route on the existing Leaflet map with 5.2 km / 6.6 min. This browser route used the current simulated traffic multiplier.
- Live backend: health and route endpoints returned HTTP 200; offline history returned HTTP 202 and `persisted: false`. Traffic `heavy` was reflected by a reported 1.8 multiplier and duration calculation.
- Browser: dashboard and OpenStreetMap tiles rendered; marker click changed the source and triggered a successful road-route API response; demo mode returned a successful synthetic route; history was labeled temporary; mobile layout measured no horizontal overflow at a 390px configured viewport (browser content width 312px, document width 300px).
- Process check: one verified SmartRoute process on port 5000; Vite process on port 5173.
- Security: server production audit has 0 findings; client audit has 3 moderate Tailwind/PostCSS findings.
- TomTom: mocked integration tests pass for live parameters, alternative selection, duration/distance objective selection, missing key, 401/403, 429, 5xx, timeout, malformed/no-route responses, and OSRM fallback. `server/.env` has no `TOMTOM_API_KEY`; no live TomTom call was made.

## Known limitations

- Atlas data persistence and restart survival remain blocked until the URI is corrected and SRV resolution/connection succeeds.
- Genuine live traffic is implemented but blocked from live verification until a TomTom API key is added to `server/.env`. No TomTom credentials were created or requested in chat.
- Public OSRM demo service is best-effort and rate-limited; use a self-hosted or contracted provider for production.
- The six curated endpoints are available only in demo-graph mode; arbitrary location search is implemented through Nominatim.
- Public Nominatim/OSRM are rate-limited/best-effort services; sustained production usage needs self-hosting or a contracted provider. Nominatim is cached and throttled to one uncached request per second. A live Nominatim check returned HTTP 503 after earlier successful live tests.
- Traffic values are reproducible scenario multipliers, not observed/live traffic data.
